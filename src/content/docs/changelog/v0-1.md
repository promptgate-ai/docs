## 0.1.0 - 2026-10-16

First release of the Go core: PromptGate as a single, self-contained
binary. It succeeds the Laravel implementation (v1.x, now archived as
[promptgate-laravel](https://github.com/promptgate-ai/promptgate-laravel));
the AI Gateway, API Gateway, MCP and guardrail surfaces of v1.x return in
later 0.x releases.

### Added

- **Agent proxy** — drop-in OpenAI and Anthropic API paths
  (`/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`,
  `/v1/responses`, `/v1/models`, `/v1/messages`,
  `/v1/messages/count_tokens`). Pointing `OPENAI_BASE_URL` or
  `ANTHROPIC_BASE_URL` at PromptGate is the whole integration.
- **True streaming** — response bytes are forwarded as they arrive; no
  buffering between provider and client.
- **Provider catalogue** — built-in presets for openai, anthropic, gemini,
  groq, mistral, together, deepseek, openrouter, xai and ollama; any preset
  can be overridden and custom OpenAI-compatible upstreams added in YAML.
- **Routing** — provider chosen by `X-PromptGate-Provider` header, a
  `provider:model` prefix, the distinctive prefix of a passthrough key
  (`gsk_…` → groq) or the default provider (`--provider`, default openai).
  OpenAI-format requests can target Anthropic through its OpenAI-compatible
  API.
- **Keys** — callers either pass their own provider key through or use a
  `pg_` key that unlocks the server-side provider keys, optionally limited
  to specific providers. Requests without a key are rejected; server keys
  are never used anonymously.
- **`promptgate keys`** — create (shown once), list, revoke, enable,
  delete. Only SHA-256 hashes are stored (`keys.yaml`, 0600).
- **Request log** — every request, including rejected ones, with
  provider, model, status, TTFB, duration, token usage and cost, in a local
  SQLite database. Token usage is read from responses while they stream;
  costs come from an embedded price table (378 models, generated from
  LiteLLM) with YAML overrides. Retention is configurable.
- **`promptgate logs`** (filters, `--follow`, `--json`) and
  **`promptgate stats`** (requests, errors, p50/p95 latency, TTFB, tokens,
  cost; `--by provider|model|key`).
- **Live console** — `promptgate start` prints one line per request in a
  terminal and stays quiet as a service (`logging.console`, `--quiet`).
- **Configuration** — one YAML file in the OS config directory, strict
  validation (unknown keys are errors), `${ENV}` references, and the
  precedence flag → environment → file → default for every setting. Config
  and keys reload automatically on change (and on SIGHUP); an invalid
  change keeps the running config.
- **CLI** — `setup` (commented config + first `pg_` key), `start`, `info`,
  `validate`, `version`, `install` / `uninstall` / `service` (launchd,
  systemd, Windows service; per-user by default), `update`.
- **Distribution** — binaries for Linux, macOS and Windows on amd64 and
  arm64, `.deb`/`.rpm`/`.apk` packages and a distroless container image.
  `curl -fsSL https://install.promptgate.dev/install.sh | sh` and
  `irm https://install.promptgate.dev/install.ps1 | iex` install with
  checksum verification.

### Security

- Releases are signed: `checksums.txt` carries an Ed25519 signature;
  `promptgate update` installs only when the signature verifies against the
  key compiled into the binary and the download matches its checksum.
- Upstream redirects are never followed, so credentials can't leak to
  other hosts; client cookies and credentials are not forwarded upstream.
- The request scanner reads duplicate and escaped JSON keys exactly like
  the providers do, so crafted bodies can't bypass routing decisions.
- The gateway listens on `127.0.0.1` by default and warns when exposed
  beyond localhost.

### Performance

Measured against the Laravel v1.0.0 baseline on the same machine (see
`bench/results/`):

- Gateway overhead at p50: **0.14 ms** (Laravel: ≈ 24 ms).
- Throughput with 16 concurrent clients: **≈ 22,000 req/s** (Laravel: ≈ 83).
- Streaming time to first byte: **0.27 ms** (Laravel: only after the full
  response).
- Request logging adds no measurable latency; the log writer sustains
  ≈ 190,000 rows/s and `stats` answers in ≈ 70 ms over one million requests.
- 14 MB binary (5.6 MB download), ready in ≈ 50 ms, ≈ 24 MB RAM at idle.
